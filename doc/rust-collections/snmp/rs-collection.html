Centreon Rust SNMP collection

Type: object

Declarative definition of a check executed by the centreon-plugin-rust-snmp binary (see rust-plugins/).

A collection describes three stages, run in order:

  1. collect — the SNMP queries to perform against the target;
  2. compute — the metrics (and optional aggregations) derived from the collected values, with their thresholds;
  3. output — how the resulting status and metrics are rendered as a Monitoring Plugins compatible message.

The file is passed to the binary with --json / -j.

root collect snmp SNMP query name
Type: string

Macro name under which the collected value is exposed to expressions.

Without labels, the value is referenced as {name}: a scalar for a Get query, a vector (one entry per row) for a Walk.
With labels, one macro per label is created instead, named {name.<label>}.

Must be at least 1 characters long


Examples:

"storage"

"memory_used"

root collect snmp SNMP query oid
Type: string

OID to query, in numeric dotted form. A leading dot is accepted and ignored.

For a Get query this must be a leaf OID (index included, usually ending in .0); for a Walk it is the root of the subtree to traverse.

Must match regular expression: ^\.?[0-9]+(\.[0-9]+)*$
Examples:

"1.3.6.1.2.1.1.1.0"

".1.3.6.1.2.1.25.1.1.0"

"1.3.6.1.2.1.25.2.3.1"

root collect snmp SNMP query labels
Type: object

Splits a Walk over a table into one named macro per column. Only meaningful with "query": "Walk".

Each key is the column part of the OID — the walked OID minus its trailing row index — matched as a suffix, so both ".2" and "2" select column 2. Each value is the label appended to the query name, giving the macro {<name>.<label>}.

Example: walking 1.3.6.1.2.1.25.2.3.1 under the name storage with {".3": "description", ".6": "used"} yields the vectors {storage.description} and {storage.used}, aligned row by row.


Example:

{
    ".3": "description",
    ".5": "size",
    ".6": "used"
}

Metric

Type: object

A value to compute, threshold and report as perfdata.

 No Additional Properties

root compute metrics Metric name
Type: string

Metric name, reported in the perfdata and used to reference the result as {metrics.<name>} or {aggregations.<name>}.

For a metric evaluating to a vector, the perfdata is named '<instance>#<name>', the instance coming from prefix.

Must be at least 1 characters long


Examples:

"storage.usage.bytes"

"system.uptime.seconds"

root compute metrics Metric value
Type: string

Expression producing the metric value. A scalar expression yields one perfdata; a vector expression (a Walk macro, or an arithmetic combination of vectors) yields one perfdata per row.

Syntax: numbers, + - * /, parentheses, macros in braces ({storage.used}), and the functions Average(...), Min(...) and Max(...), which reduce a vector macro to a scalar.

Must be at least 1 characters long


Examples:

"{storage.used} * {storage.allocation_units}"

"100 * {storage.used} / {storage.size}"

"Average({metrics.cpu.utilization.percentage})"

root compute metrics Metric prefix
Type: string

Template naming each instance of a vector metric, interpolated with the collected macros — usually the label column of the walked table.

When omitted, instances are numbered from 0. The resulting name is what --filter-in and --filter-out match against.

The template is only interpolated for a metric evaluating to a vector; for a scalar metric, and for any aggregation, the string is used as-is.


Examples:

"{storage.description}"

"{inodes.path}"

root compute metrics Metric threshold-suffix
Type: string

Exposes the metric on the command line as --warning-<suffix> and --critical-<suffix>; those options override the warning and critical fields below. Metrics without a suffix cannot be thresholded from the command line.

The suffixes of a collection are listed by --list-counters.

Must be at least 1 characters long


Examples:

"usage"

"prct"

"seconds"

root compute aggregations
Type: array

Second-pass metrics, computed after metrics and able to reference them as {metrics.<name>} — typically to sum or average a per-instance metric into a global one.

The pass is skipped entirely when every instance has been discarded by --filter-in / --filter-out. Each aggregation is exposed as {aggregations.<name>}, usable in output templates.
